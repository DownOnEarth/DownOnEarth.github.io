Host Discovery

Usage

Note : If hosts are marked inactive it may just mean that they ignore ICMP requests.

Scan a network :

sudo nmap <network> -sn | grep for | cut -d" " -f5

Scan specific addresses :

sudo nmap -sn <targetA> <targetA> <targetA> | grep for | cut -d" " -f5

Scan a range of addresses (format : X.X.X.X-X) :

sudo nmap -sn <IPRange> | grep for | cut -d" " -f5

Scan from a host list :

sudo nmap -sn -iL <hostsListFile> | grep for | cut -d" " -f5

Force detection through ICMP and not ARP (OS detection) :

sudo nmap <host> -sn -PE --packet-trace --disable-arp-ping

Port Scanning

Documentation

Possible states

StateDescription
openThis indicates that the connection to the scanned port has been established. These connections can be TCP connections, UDP datagrams as well as SCTP associations.
closedWhen the port is shown as closed, the TCP protocol indicates that the packet we received back contains an RST flag. This scanning method can also be used to determine if our target is alive or not.
filteredNmap cannot correctly identify whether the scanned port is open or closed because either no response is returned from the target for the port or we get an error code from the target.
unfilteredThis state of a port only occurs during the TCP-ACK scan and means that the port is accessible, but it cannot be determined whether it is open or closed.
open|filteredIf we do not get a response for a specific port, Nmap will set it to that state. This indicates that a firewall or packet filter may protect the port.
closed|filteredThis state only occurs in the IP ID idle scans and indicates that it was impossible to determine if the scanned port is closed or filtered by a firewall.

Scan options

  • -sS (SYN only)
  • -sT (TCP 3 way handshake)
  • -sA (ACK only)
  • -sU (UDP scan)

Note : if run with root, default set to -sS, otherwise -sT (easily detected but more accurate, logs may be kept), -sA may be relevant as firewalls do not know if the traffic is incoming or requested.

Usage

Scan one port / multiple ports / port range / top 100 ports / all ports :

nmap [-p X] [-p X,Y] [-p X-Y] [-F] [-p-] <target>

Packet trace with disabled ICMP echo (-Pn) disabled ARP (--disable-arp-ping) and DNS resolution (-n) and display the reason a port is in its particular state :

sudo nmap <target> -p <port> --packet-trace -Pn -n --disable-arp-ping --reason

Version detection

Add argument -sV for version scanning. A version scan may be quite long and noisy, therefore should be done after a quick port scan :

  • Press [spacebar] during scan to show status or specify --stats-every=<X>s.
  • -v / -vv to display opened ports upon detection.

Scripting Engine

Documentation

Scripting categories

CategoryDescription
authDetermination of authentication credentials.
broadcastScripts, which are used for host discovery by broadcasting and the discovered hosts, can be automatically added to the remaining scans.
bruteExecutes scripts that try to log in to the respective service by brute-forcing with credentials.
defaultDefault scripts executed by using the -sC option.
discoveryEvaluation of accessible services.
dosThese scripts are used to check services for denial of service vulnerabilities and are used less as it harms the services.
exploitThis category of scripts tries to exploit known vulnerabilities for the scanned port.
externalScripts that use external services for further processing.
fuzzerThis uses scripts to identify vulnerabilities and unexpected packet handling by sending different fields, which can take much time.
intrusiveIntrusive scripts that could negatively affect the target system.
malwareChecks if some malware infects the target system.
safeDefensive scripts that do not perform intrusive and destructive access.
versionExtension for service detection.
vulnIdentification of specific vulnerabilities.

Usage

Run scripts

Default scripts (trace commands sent with --script-trace) :

sudo nmap <target> -sC --script-trace

Specific script category :

sudo nmap <target> --script <category>

Defined scripts :

sudo nmap <target> --script <script-name>,<script-name>,...

Aggressive scan (-A) - Service, OS, traceroute and default scripts :

sudo nmap <target> -p <port> -A

Search scripts

Search for all scripts containing <value> (smtp, ftp, nfs, smb, mysql, …) :

ls -al /usr/share/nmap/scripts/ | grep -e "<value>"

Firewall and IPS/IDS Evasion

Usage

Decoys

Random IP addresses are generated -D, the real IP placed among them, decoys must be alive to avoid unreachability due to SYN-flooding :

sudo nmap <target> -p <port> -D RND:<numberOfFakeIPs>

Changing IP source address -S :

sudo nmap <target> -p <port> -S <sourceIP> -e <interface>

Changing source port --source-port (for example 53 - DNS - to exploit less monitored ports) :

sudo nmap <target> -p <port> --source-port <sourcePort>

connect through netcat to opened port 50000 from port 53 :

ncat -nv --source-port 53 <target> 50000

Storing Results

Documentation

  • Normal output (-oN) with the .nmap file extension
  • Grepable output (-oG) with the .gnmap file extension
  • XML output (-oX) with the .xml file extension
  • All the above (-oA)

Usage

Register results in all formats :

sudo nmap <target> -oA results

Convert results from xml to html :

xsltproc results.xml -o results.html
